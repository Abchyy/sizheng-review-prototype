# 科研实训与黑客松：一页讲清楚

**问题：** 大模型对整篇材料逐段审校会产生延迟与费用，也可能凭记忆把日期或范围说错。快速模型容易漏检；知识库不完整，没查到也不能直接判错。

**方案：** 程序管理上下文与模型；JEV 作初步分流，图谱提供原文与出处，DeepSeek 处理语境，引用验证和人工复核兜底。明确事实断言不允许由快速模型直接放行。

**例子：** 文本把学校思政课座谈会讲话日期写成 2020-09-01。图谱分别记录讲话发生于 2019-03-18、相关文章发表于 2020-09-01。大模型结合上下文区分两个事件，再输出依据。若文本是在批评这个错误，而不是声称该日期正确，就不应误报。

**评测：** 用固定的 24 条合成测试案例比较 LLM 单独、LLM＋图谱、JEV＋LLM＋图谱。看三类判断准确率、问题召回率、误报、自动无问题建议中的错误、证据编号与原句有效性、深度调用数、耗时与费用。没有领域专家标注，因此不能把成绩当作生产效果。

**取舍：** 事实密集稿件几乎都要深审，JEV 可能增加开销；快速模型是否值得加入，需要看真实流程中一般描述和复杂断言的比例。不是组件越多就越好。

**现场展示：** 先运行离线图谱和验证命令，演示范围错误、时间混用、引述纠错、未知文件；再展示真实 API 结果与三方案对照。清楚说明原型已做到什么、尚无什么依据，比宣称“完全智能审校”更有说服力。

**扩展路线：** 用真实专家标注材料补齐语料和错误类型→按原文/版本簇拆分→评测证据的语义支持→在开发集选择阈值→独立盲测→再考虑 Neo4j、混合检索、BERT 蒸馏和生产权限。
